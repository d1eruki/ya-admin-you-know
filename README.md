# ya-admin-you-know

Единая админка для обновления контента сайтов на разных доменах и хостингах. После разового подключения сайта редакторы и разработчики меняют тексты и изображения в админке. Поля собираются автоматически, а внешний вид задают шаблоны самого сайта.

Версия: `0.5.2`.

## Запуск админки

Запустите `npm run dev` и откройте `http://127.0.0.1:5173/`. Адрес API для разработки задаётся через `VITE_API_URL`.

### Локальный API

1. Выполните `npm install` и `npm run db:migrate`. В локальном `.dev.vars` задайте `AUTH_SECRET` со случайным значением длиной от 32 символов и ключ отправки `RESEND_API_KEY`.
2. Добавьте тестовый сайт в локальную D1. Укажите полный HTTPS-адрес с завершающим слешем и почту аккаунта Resend:

   ```sh
   npm exec wrangler -- d1 execute DB --local --command "INSERT INTO sites (address, name, email) VALUES ('https://portfolio.example.com/project/', 'Портфолио', 'editor@example.com');"
   ```

3. Запустите `npm run dev:api` и в отдельном терминале `npm run dev`. Запрос кода отправляет письмо на адрес сайта. Отправитель `onboarding@resend.dev` доставляет только на почту аккаунта Resend.

Для облачного входа и работы с изображениями привяжите D1 и приватный R2, примените миграции, задайте `AUTH_SECRET` и `RESEND_API_KEY` как секреты Worker, а адрес интерфейса добавьте в `ALLOWED_ORIGINS`. При сборке интерфейса укажите HTTPS-адрес Worker через `VITE_API_URL`. Для публичной админки предусмотрите отдельный origin, например выделенный поддомен, и включите двухфакторную защиту на почте сайта.

## Проверки безопасности

Для автотестов подготовьте локальную копию Port Heaven из ветки `ya-admin-content-secure-local` с установленными npm-зависимостями. Выполните `npm run check:local-security -- /путь/к/port-heaven`. Добавьте `--browser` для проверки формы отзыва сеансов в Chrome.

Тесты сами создают временные D1 и R2, перехватывают тестовые письма и имитируют публикацию локально. После прогона окружение останавливается, а временные данные удаляются.

## GitHub Pages

Интерфейс публикуется по адресу [d1eruki.github.io/ya-admin-you-know/](https://d1eruki.github.io/ya-admin-you-know/) после обновления ветки `main`. В переменной репозитория `ADMIN_API_URL` задаётся HTTPS-адрес Worker. GitHub Actions проверяет опубликованные страницы через Lighthouse.

## Стек и размещение

- **Интерфейс.** Vue, Vite и TypeScript. Готовая статическая сборка админки размещается на GitHub Pages.
- **Сервер.** Cloudflare Workers обслуживает API админки. Для локальной разработки и выкладки Worker используется Wrangler.
- **Хранение.** Cloudflare D1 хранит настройки сайтов, значения полей, черновики и версии публикаций. Файлы изображений хранятся в Cloudflare R2.
- **Почта.** Одноразовые коды отправляет Resend. Для первого пилота используется тестовый отправитель `onboarding@resend.dev`.
- **Выкладка сайтов.** Подключённые сайты сохраняют свой стек и хостинг. Для статического сайта Worker запускает GitHub Actions, который собирает сайт, коммитит обновлённые файлы контента в репозиторий сайта и выкладывает сборку.

## Что работает сейчас

После входа по адресу Port Heaven админка читает манифест из GitHub. В дереве доступны русские тексты, существующие проекты и макеты, а также превью изображений. Манифест берётся из интеграционной ветки `ya-admin-content-fields`, подготовленной от опубликованной ветки сайта.

Черновик общий для сайта. Текст и ссылки на загруженные изображения хранятся в D1, файлы черновика — в приватном R2. Кнопка «Опубликовать» появляется после настройки GitHub Actions и ветки публикации.

Для публикации настройте `GITHUB_PUBLISH_TOKEN` с разрешением Actions: write на репозиторий сайта и общий секрет `PUBLISH_WORKFLOW_SECRET` в Worker и GitHub Actions. Для шифрования файлов между заданиями добавьте секрет Actions `PUBLISH_ARTIFACT_KEY` из 32 случайных байт в виде 64 шестнадцатеричных символов. Укажите репозиторий в переменной Worker `PUBLISH_REPOSITORY` и HTTPS-адрес API в переменной GitHub Actions `ADMIN_API_URL`. В настройке сайта в D1 задайте одинаковые `source_ref` и `publish_ref`, когда процесс публикации доступен в выбранной ветке.

## MVP

Первая версия позволяет менять тексты и изображения на страницах и в существующих карточках, сохранять черновики и публиковать изменения. На этом этапе у сайта один язык редактирования.

### Подключение сайта

Разработчик один раз подключает плагин сбора контента и настраивает сборку и выкладку сайта в GitHub Actions. В админке указывает домен, подтверждённую почту для входа, репозиторий и ветку публикации. Первая интеграция рассчитана на сайты с Vue и Vite.

### Автоматический сбор контента

1. При изменениях в репозитории GitHub Actions запускает генератор. Он извлекает распознаваемые тексты и изображения из шаблонов Vue, ключи и начальные тексты из словарей i18n, а также поля существующих карточек из подключённых файлов данных. Для типовых полей достаточно добавить контент в исходный код. Явная привязка нужна, если по коду нельзя однозначно определить поле или место его использования.
2. Генератор создаёт в ветке сайта один `content-manifest.json`. Для каждого поля там хранятся постоянный ключ, подпись, тип и значение. Для изображений значение — путь к файлу в репозитории. При повторной генерации новые поля получают начальные значения, а правки по существующим ключам сохраняются.
3. Админка читает манифест прямо из GitHub и автоматически обновляет дерево, сохраняя черновики по существующим ключам. Сборка сайта подставляет значения из того же манифеста по этим же ключам.

### Вход по адресу сайта

Доступ в MVP привязан к сайту и его почте для входа. Персональные аккаунты не требуются.

1. При подключении сайта указывают его полный адрес и почту для входа.
2. Редактор вводит адрес сайта в общей админке и нажимает «Получить код». Если сайт расположен в подпапке, как проект на GitHub Pages, адрес включает и этот путь.
3. Админка отправляет одноразовый код на почту, привязанную к сайту. Редактор вводит код на странице входа.
4. После проверки кода админка открывает дерево контента этого сайта. До выхода редактор может менять поля, сохранять черновики и публиковать изменения в пределах этого сайта.

### Редактирование и публикация

1. **Дерево полей.** Админка группирует поля по страницам, секциям и существующим карточкам. Например, `home.hero.title` и `home.hero.cover` появляются рядом в секции «Главная → Первый экран». По типу поля админка показывает ввод текста или миниатюру с кнопкой «Заменить». Общие для нескольких страниц поля можно редактировать в одном месте.
2. **Редактирование.** Редактор или разработчик правит текст или заменяет картинку в админке и сохраняет черновик. Сайт продолжает показывать последнюю опубликованную версию.
3. **Публикация.** По кнопке «Опубликовать» Worker фиксирует версию черновика и запускает GitHub Actions. Actions берёт актуальную ветку, применяет правки к выбранным полям в `content-manifest.json`, добавляет новые изображения и собирает сайт. После успешной сборки он сам отправляет один коммит с манифестом и изображениями в ветку публикации и выкладывает эту же сборку.
4. **Результат выкладки.** Статус «Опубликовано» появляется после успешной выкладки. Если то же поле изменилось в репозитории с момента создания черновика, админка показывает конфликт и сохраняет черновик. При ошибке сборки коммит не отправляется. При ошибке выкладки после отправки коммита он остаётся в Git, а сайт показывает предыдущую версию. В обоих случаях админка показывает ошибку и сохраняет черновик.
5. **Локальная синхронизация.** Чтобы получить правки из админки, разработчик переключается на ветку публикации сайта и выполняет `git pull`.

## После MVP

- **Английский контент.** Редактор выбирает `RU` или `EN` у одного и того же поля. Ключ и место поля в дереве общие для обоих языков.
- **Добавление записей по шаблону.** Кнопка «+» в списке открывает форму с полями новой записи. После публикации сайт выводит запись в существующем шаблоне, например в виде карточки товара или проекта.
- **Telegram.** Редактор выбирает доступный домен, поле и при необходимости запись, затем отправляет новый текст. Бот сохраняет изменение как черновик в админке с учётом прав редактора.

- **Стилизация** добавить подсос стилей типа иконку название цвета шрифты
- **Филтры текстов** добавить фильтры типа подписи изображений заголовки
